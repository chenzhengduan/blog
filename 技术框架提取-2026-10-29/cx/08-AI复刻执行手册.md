# AI 复刻执行手册

## 交给实现代理的任务说明

```text
你要重建CX教育AI平台及其xzagent对话接入。先读README、01、02，再读与你实现阶段相关的章节和assets。
必须区分：源码事实、配置样例、建议步骤和当前缺失资源。禁止把企业微信Bot、本地聊天LLM或通用可视化DAG编排描述为本项目已有实现。
业务层负责题型/结构/租户/持久化校验；模型通过结构化工具提交候选，不能只靠Prompt约束。
CX与xzagent使用不同AgentScope版本和身份协议，分别实现适配，不要擅自统一依赖或合并数据模型。
先建立最小纵向链路，再逐层增加功能，每层满足本手册的验收条件后继续。
真实密钥由环境注入；不把模板示例当真实账号，也不把测试SQL当当前生产DDL。
记录所有无法从资料确定的外部参数；用占位接口隔离缺口，明确它们不能通过真实联调。
```

本手册能提供职责、协议、配置、核心Prompt和验收标准。它不包含完整业务源码、模型服务账户、生产数据库数据或xzagent正式DDL，因此是可执行的重建依据，不能声称文档包单独即可零配置启动原系统。

## 阶段一 基础设施和身份闭环

输入：01/02/07章，CX schema，三个Java项目依赖清单及配置附件。

1. 建立Gateway、Backend、Frontend、Python、xzagent五个独立运行单元。
2. CX以Controller→Service→Mapper→DO分层；WebFlux保留阻塞JDBC隔离点。
3. 导入CX schema，建立应用种子并用BCrypt存secret。
4. 实现公开换Token、Redis缓存、网关核验、appId上下文与租户过滤。
5. 接入OpenAPI、统一错误、Long字符串与健康检查。

验收：应用A能换Token并访问自己数据；过期/错误凭据401；Redis失败按现有契约503；跨应用资源不泄漏；前端不因JS整数精度损失ID；后端不直接暴露给不可信客户端。

## 阶段二 单题生成纵向链路

输入：模型章、`assets/prompts/question-agent`、`assets/backend-skills/chuti`。

1. 实现命名模型端点与任务路由，至少一个有效模型。
2. 使用实际provider SDK构造参数并测试对应协议，校验base-url拼接。
3. 为每次请求创建Agent和工具；加载学科Skill与system/user prompt。
4. 模型产出结构化题目后校验题型、选项/答案、子题与图信息，落question表。
5. 发出task/progress/result/error业务SSE，前端正确消费。

验收：一条合法请求得到可查询的题目；格式错误能受控失败；请求取消/断线行为明确；实际用量归因到appId；模型生成文本不能绕过业务字段校验。

## 阶段三 整卷 变式与批改

输入：ExamChutiAgentV2对应工具、exam-agent v2提示词、变式与grading提示词。

整卷按大纲和题目提交工具形成可检查结构；题位使用稳定sectionQuestionId；变式保留来源；答卷、逐题答案与批改任务单独持久化。每类任务独立配置模型路由与预算，不用一个超长Prompt兼任所有流程。

验收：题型/题数/分值一致；重生成不会破坏原题位；按题位可回查答卷；批改结果有得分和反馈；PDF/Word打开后公式、中文和图像可见；导出资源超限可控失败。

## 阶段四 录题与本地图检测

输入：04章、cx-py manifest/lock、录题提示词、schema中的三类公共任务表。

1. 按固定版本准备CPU模型环境，下载指定revision权重并校验SHA-256。
2. 实现Python就绪、容量限制、图片输入安全边界、检测坐标和增强接口。
3. Java通过统一内部客户端调用，不把Python挂到公网通配路由。
4. 实现Outbox+Redis Streams调度：原子落任务/步骤/outbox、事务外执行、fencing后提交。
5. 按材料页识别、图检测、答案和草稿装配推进；人工确认后再产生正式题目。

验收：模型未就绪不能成功检测；坐标与原图对应；队列满返回可判定错误；断开浏览器任务可查询；在阶段执行中重启worker不会重复提交陈旧结果；重复消息不会重复写正式业务数据。

## 阶段五 知识点匹配

输入：knowledge_tree/point/embedding表、Embedding配置、knowledge-point-match提示词。

先导入并建立向量，再对题目做召回和受控选择。模型只能在当前可见候选中选合法ID，缺少证据可不匹配，不能生成不存在的知识点名称就直接落库。向量模型或维度变更要重建索引。

验收：同一题可返回树内合法节点；跨租户不可见；索引未就绪有明确状态；无法匹配记录与正常空结果可区分；TopK和模型选取上限符合04章。

## 阶段六 xzagent 对话运行时

输入：05章、xzagent API说明、当前正式数据库资产。

1. 建立应用与用户JWT鉴权、资源归属、模型配置和加密存储。
2. 构建HarnessAgent、数据库状态存储、SkillHook及实际启用能力。
3. 实现AG-UI事件循环、Run/session关系、Redis事件补流、跨节点取消与终态收口。
4. 实现local/MCP/remote工具绑定、用户凭据、OAuth与出站地址校验。
5. 保持默认能力开关；不因为框架支持Shell、子Agent等就默认全部打开。

验收：相同session不能切换agentId；断线重连不产生第二次业务Run；取消找到owner节点；旧Run事件不污染新Run；未授权工具要求授权；失联Run有终态而非永久运行。

## 阶段七 CX Bundle与网页对话

输入：06章、`assets/cx-bundle`。

修改Bundle环境里的域名、Meta地址、source绑定和OAuth参数，校验工具名称和schema匹配实际API。先预览导入再按平台导入流程执行。CX enter-chat完成app-token→user-login-bind两阶段转换，浏览器使用User JWT调用AG-UI。

先处理06章列出的录题取消兼容问题：当前Meta声明DELETE，而远程执行器只支持GET/POST；在修复并测试前不得把该工具验收为可用。对于05章中未确认生效的旧AutoContext参数，也应做行为验证，不以配置加载成功代替功能生效。

网页A2UI根据Catalog渲染，交互必须按原动作协议回传；不能把模型生成的任意HTML当可信UI执行。远程工具失败需要以工具错误交给对话，而不是将业务错误吞掉并继续声称成功。

验收：用户自然语言请求出卷，Agent调用远程工具，CX生成真实试卷，前端显示可打开的结果链接；过程中可见进度；无凭据时显示授权流程；授权取消不会调用业务。

## 阶段八 飞书渠道

输入：03章，已有可运行xzagent，飞书应用权限。

先实现平台特定注册和Channel适配，再复用统一Run。管理员绑定身份、飞书发言人身份和CX操作人凭据分别处理。出站WebSocket接收消息，验证群聊触发、去重、附件、分段回复、连接重建，以及统一Run的取消与节点协调。

验收：绑定成功不等于连接成功；相同消息不重复执行；不同群/用户不会串会话；群成员不能继承管理员私有工具授权；长回复可读；附件超限受控；服务重启后的连接状态可观察。

企业微信属于新增工作：必须重新取得企业微信官方协议、凭证、回调/长连接能力与应用权限设计，再实现独立渠道适配。本资料不提供虚构的企业微信线上接入步骤。

## 最小验收矩阵

| 层 | 成功场景 | 失败场景 | 证据 |
|---|---|---|---|
| 配置 | 生效模型路由合法 | 缺端点启动失败 | 启动诊断与最终配置键，脱敏 |
| 身份 | 合法应用访问自身资源 | 跨租户、过期凭据 | HTTP状态和隔离测试 |
| 业务Agent | 一题、一卷可回查 | 非法JSON/题数不符 | DB结果、SSE、结构验证 |
| 本地视觉 | 基准图片坐标正确 | 哈希错误/未就绪/过载 | 模型ready与检测样例 |
| 异步任务 | 重启后恢复 | 重复消息/陈旧worker提交 | runVersion/fencing与结果唯一性 |
| 对话 | 工具调用完成 | 授权缺失、远程超时 | AG-UI终态与工具事件 |
| 渠道 | 飞书消息与回复 | 重复、群身份、连接失败 | 渠道状态及真实消息记录 |
| 导出 | 中文、公式、图片正确 | 超限或非法资源URL | 文件渲染和错误响应 |

## 开发验证命令

分别在对应仓库执行，测试需要其依赖环境，不要在生产数据上直接跑集成用例：

```text
cx-backend:  mvn test
cx-gateway:  mvn test
xzagent:     mvn test
cx-frontend: pnpm typecheck
cx-frontend: pnpm test:run
cx-frontend: pnpm build
cx-py:       python -m pytest
```

当前源码测试用例可用作实现契约参考，但“仓库有测试”不等于本次已运行通过。本次文档提取只验证文档、引用和附件，不声称通过上述构建、真实模型、Bot或数据库联调。

## 如何修改而不丢失设计

新增业务先添加Controller/DTO/Service/表结构，再把它包装为远程工具Meta和Skill；不要先给模型一个没有实现的工具。新增模型先做协议契约验证再写任务路由；新增渠道先处理身份、消息生命周期与交付，再接Runtime。修改提示词要同时检查结构化工具/schema及业务校验是否仍一致。

每次完成一条纵向链路，都记录有效配置的脱敏版本、模型ID、代码版本、验收输入和结果。这样AI能接续真实进度，不会把演示页面或模拟返回当成实现完成。
