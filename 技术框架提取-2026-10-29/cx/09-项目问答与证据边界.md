# 项目技术问答与证据边界

## 三十秒讲清项目

CX是教育AI能力平台，Java业务服务负责题目、试卷、录题、批改、知识点和导出，Vue前端提供操作页面，Gateway负责开放平台入口。业务后端直接用AgentScope调用模型，Python服务本地运行DocLayout-YOLO做题内图检测。独立的xzagent提供通用对话、Skill、远程工具、A2UI和飞书渠道，通过HTTP工具调用把CX业务能力接到自然语言入口。

## 常见技术问题

### 用什么后端框架 为什么是WebFlux

CX和xzagent主要是Spring Boot 3.5.8 + WebFlux，网关是Boot 3.2.0配Cloud 2023.0.0。WebFlux承载模型流、SSE和外部HTTP的响应式链；数据库仍是MyBatis/JDBC，需把阻塞操作移出Netty线程，不能说整个系统完全非阻塞。见01/02章。

### 为什么还需要xzagent CX自己不是也能调用模型吗

CX调用模型完成有明确领域约束的教育任务。xzagent处理通用对话会话、工具授权、Skill装配、动态UI和渠道消息。CX把业务接口封装为远程工具供xzagent调用，因此两者是业务执行与通用交互协作关系。见02/05章。

### 模型怎么接入 用了哪些模型

CX以命名endpoint+task路由接入OpenAI兼容、Anthropic和DashScope。模板出现gpt-4o-mini、Claude Sonnet、qwen-max、text-embedding-v4、wan2.7-image和dall-e-3等名称；这说明模板支持的配置示例，不证明线上采用这些模型。xzagent模型配置由数据库资源与运行快照管理。具体协议、fallback和限制见04/05章。

### 哪些模型是本地部署

代码中明确落地的是cx-py的DocLayout-YOLO CPU模型，权重有固定revision、大小与SHA-256。未发现本地大语言模型推理服务的一键部署资产。OpenAI兼容URL可以扩展到其他服务，但那不是已经部署本地LLM的证据。见04章。

### 飞书Bot怎么接入

当前使用飞书SDK，用户扫码注册/绑定应用后，由xzagent主动建立WebSocket长连接接收消息，转为统一Channel Run调用Runtime，最终再将回复发回飞书。绑定密钥加密保存，消息去重、身份映射、群聊会话、媒体和消息切分分别处理。不是一个简单的群机器人Webhook转发脚本。见03章。

### 企业微信Bot怎么接入

本次检查的两个项目当前源码没有找到企业微信Bot渠道实现。不能把飞书流程换个名称当作企微方案。可复用的是xzagent统一渠道运行层；平台鉴权、事件接收、用户和群映射、消息发送仍需单独实现并对照官方协议验证。

### 编排是工作流引擎还是Agent

至少要分三层：CX业务Agent执行ReAct工具循环；xzagent当前使用HarnessAgent装配对话能力与工具；录题等长任务使用数据库状态机、Outbox和Redis Streams的可恢复步骤。它们解决不同问题，未核验到一个统一可视化DAG设计器承担全部编排。见02/05章。

### Skill到底是什么

CX业务Skill从classpath装配，包含学科出题/批改/变式等知识和参考资料；xzagent Skill运行来源是数据库，Bundle只是导入载体。Skill提供何时用工具、如何完成任务的指引，工具定义和凭据绑定决定实际执行能力；光复制SKILL.md不等于实现业务。见06章及附件。

### A2UI和AG-UI有什么区别

AG-UI负责对话运行和事件传输，A2UI描述可渲染的UI结构与交互。xzagent的Catalog定义组件约束，前端按目录渲染并回传动作。二者不应与CX task/progress/result业务SSE混为一谈。见02/05/06章。

### Token和JWT是一回事吗

不是。CX短期at_ Token是Redis保存的不透明随机凭据，还有ak_长期API Key；xzagent用其应用/用户JWT体系。enter-chat负责跨体系转换及远程工具凭据绑定。见02章。

### 如何隔离不同接入方

CX由网关从凭据确定appId，后端读取X-App-Id到Reactor Context，数据按app_id过滤。external_user/org是接入方业务标识，不承担跨租户隔离。后端不能直接暴露给可伪造Header的不可信调用方。xzagent另有app/agent/user资源边界。见02/05章。

### 前端断线会不会停止生成

普通CX生成通过独立订阅让后台执行与SSE连接分离，前端保存taskId再查询。录题有持久步骤恢复；xzagent有Run租约、事件Redis Stream、重连补流和终态处理。断线继续与进程崩溃恢复是不同保证，必须具体到链路。见02/05章。

### 知识点识别是不是RAG

可以描述为面向知识点体系的向量召回加模型受控选择：pgvector存向量，Embedding生成查询向量，召回候选后在有效候选内选择。当前没有证据应称为完整的通用文档RAG产品，也没有独立reranker服务。见04章。

### 服务发现与配置为何不用Spring Cloud Alibaba

当前代码采用原生nacos-client 1.4.7，自定义EnvironmentPostProcessor、注册与发现客户端；pom注释给出的原因是规避Boot版本兼容问题。Gateway使用Spring Cloud LoadBalancer，Backend内部服务通过WebClient加解析器调用，不是统一Feign。见02/07章。

### 文档能让AI直接复刻吗

能提供技术边界、流程、准确配置结构、接口定位、全量业务Prompt、Skill和Bundle样例，以及分阶段验收标准。要完整运行原系统仍需源码、正式xzagent DDL、外部服务和合法凭据。不能把缺失的数据库或渠道实现编造为“已配好”。见08章。

## 本次核对发现的资料漂移

| 旧说法或易误判 | 当前依据与正确解释 |
|---|---|
| CX只有脚手架 | Controller/Service与29张业务表已覆盖完整教育流程 |
| CX数据库MySQL | pom的PostgreSQL驱动与pgvector DDL |
| xzagent某些类名MySQL代表当前数据库 | 当前pom指向PostgreSQL；类名不等于数据库选择 |
| 前端无鉴权 无SSE Vite7 | router存在登录守卫，AG-UI/业务SSE已实现；package.json为Vite6.4范围 |
| xzagent用旧ReActAgent/AutoContextMemory | 当前2.0.4改为HarnessAgent与新状态装配 |
| 所有AgentScope版本相同 | CX2.0.0，xzagent2.0.4 |
| 旧AutoContext压缩阈值仍必然生效 | 配置保留，但未找到当前Harness构建路径消费这些参数，见05章 |
| 工具超时统一10分钟 | xzagent当前远程SSE总预算900秒，外层工具960秒，其他链路另有预算 |
| 模板字段必然生效 | 部分飞书/生图参数在当前实现中未被消费，见03/04章 |
| 飞书二维码绑定成功即在线 | 前端绑定状态与后端WebSocket连接状态需分别确认 |
| xzagent正式DDL在本机../db | 指定位置缺失；测试快照不是生产DDL |
| 配置模板可以原样启动 | 有占位值、名称差异、未定义端点、外部依赖，需要完成配置 |
| Meta列出工具代表已全部打通 | 录题取消声明DELETE，而当前xzagent远程HTTP适配仅实现GET/POST，见06章 |

## 证据与验证范围

关键事实由具体文件与行号支持，各专题末尾有源码入口；10章集中列HTTP路由注解。附件manifest记录来源及哈希，支持发现文件后续漂移。

本次已做源码提取和文档静态核对，不包括真实模型调用、飞书注册、企业微信开发、Nacos读取、建库或部署。现有实现中的限制按专题记录，未对业务源码进行修复。后续应按08章在隔离环境执行验收，再形成部署成功的运行证据。
