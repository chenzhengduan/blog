# 配置 部署与运维

## 配置来源与优先级

仓库约定：`application.yml` 放启动及Nacos连接，`application-template.yml` 描述应发布到Nacos的运行配置，`application-local.yml` 只做本地覆盖且不提交。实际启动文件仍保留了一些业务默认项，因此复刻要检查最终Environment，不能只看模板。

**Spring不会因为文件叫application-template.yml就自动加载它。** 使用Nacos时，把内容发布到对应Data ID；完全本地时，复制并改成私有 `application-local.yml`，或用Spring配置参数显式加载。附件已替换密钥和地址，不能直接拿占位值连接生产。

CX Java加载器先拉 `<appName>.yml`，再拉 `<appName>-<profile>.yml`，通过 `addFirst` 加入PropertySources，环境专用配置优先。Nacos值可能覆盖本地值。禁用远程配置调试时同时检查 `NACOS_CONFIG_ENABLED=false` 和注册开关。

证据：`cx-backend/.../config/NacosConfigEnvironmentPostProcessor.java:47`、`:120`；网关同名类。xzagent按它自己的加载代码和模板配置，不应套用所有CX属性。

## 服务启动矩阵

| 服务 | 源码默认端口 | 本地同机建议 | 运行配置 |
|---|---|---|---|
| cx-frontend | 5173 | 5173 | Vite环境变量 |
| cx-gateway | 9511 | 9511 | cx-gateway.yml及环境专用Data ID |
| cx-backend | 9513 | 9513 | cx-backend.yml及环境专用Data ID |
| cx-py | 9514 | 9514 | Python bootstrap与cx-py配置 |
| xzagent | 9513 | **9515** | xzagent配置、profile和数据库资源 |

CX与xzagent源码默认端口冲突。表中9515是本地复刻建议，不是仓库现有默认。生产运行在不同Pod可各用9513。

注意xzagent模板中 `spring.application.name: jegent`，启动配置中是 `xzagent`。这是当前文件差异，发布Nacos前须统一预期注册名和Data ID，不能把模板整个粘贴后忽视名称变化。

## Redis前缀不同

CX使用Boot标准 `spring.data.redis.*`；xzagent当前配置使用 `spring.redis.*` 并由自身配置类读取。不可把CX配置直接粘到xzagent然后认为等价。网关模板没有完整列出Redis连接，部署时仍要显式配置与Backend一致的 `spring.data.redis`。

CX常见键族：`open_platform:token:`、`open_platform:apikey:`、`cx:async-task:dispatch:backend`。xzagent有自己的Run活跃租约与事件Stream，详见05章，不要随意共用相同业务键名。

## 本地启动顺序

下列是依据源码整理的执行手册，未在本次提取中实际运行整套依赖。每一步先通过验收再接下一步。

### 一 准备库和配置

1. 安装与项目兼容的PostgreSQL及pgvector；为CX创建空库。
2. 在空库执行 `assets/database/cx-schema.sql`。已有库改用原仓 `db/migrations` 中匹配版本的迁移，不在已有业务库重跑全量schema。
3. 准备Redis。保持CX网关与Backend数据库编号一致。
4. 在各Java项目复制模板到各自不提交的本地配置，设置实际数据库/Redis/模型参数，关闭不使用的SLS与观测；不要覆盖已有个人配置。
5. 完成本地 `open_app` 种子：app_id、应用名、BCrypt app_secret、启用状态及必要业务字段。schema只有结构，不自动产生可登录账号。
6. xzagent另需正式schema及应用/Agent/模型/资源数据；CX的open_app不是xzagent账号表的替代品。

### 二 CX Backend

Java17和Maven3.9+。在 `cx-backend` 目录，先确认 `java -version` 和 `mvn -version`。本仓约定根 `.env` 中若有JAVA_HOME/MAVEN_HOME优先使用；不要把.env内容写入文档或日志。

```powershell
$env:SPRING_PROFILES_ACTIVE = 'local'
$env:NACOS_CONFIG_ENABLED = 'false'
$env:NACOS_REGISTER_ENABLED = 'false'
$env:SERVER_PORT = '9513'
$env:CX_PY_DIRECT_BASE_URL = 'http://127.0.0.1:9514'
mvn clean install -DskipTests
mvn spring-boot:run
```

前提是本地配置已完整，不是只设置这几个环境变量就能启动所有功能。`-DskipTests` 是打包命令，不构成测试通过。健康检查：`GET http://127.0.0.1:9513/cx/health`。

### 三 CX Gateway

若本地禁Nacos，需要将本地配置里的路由 `lb://cx-backend` 改为 `http://127.0.0.1:9513`，保留Path和StripPrefix。**只关Nacos却保留lb路由会找不到实例。**

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: cx-route
          uri: http://127.0.0.1:9513
          predicates:
            - Path=/api/cx/**
          filters:
            - StripPrefix=1
  data:
    redis:
      host: 127.0.0.1
      port: 6379
      database: 0
```

这是本地覆盖片段，应合并到对应配置而非产生两个重复spring根键。在独立终端设置SERVER_PORT=9511及Nacos关闭开关后执行 `mvn spring-boot:run`。检查 `/api/cx/health` 和一次真实Token换取。

### 四 CX Python

使用Python3.11专用虚拟环境；不要使用机器上其他Python版本直接安装。优先复现原Dockerfile中的CPU wheel、DocLayout包修补及headless OpenCV过程。固定权重见 `assets/local-model/model-manifest.json`；校验脚本和启动命令详见04章。

```powershell
$env:NACOS_CONFIG_ENABLED = 'false'
$env:NACOS_REGISTER_ENABLED = 'false'
$env:CX_DETECTOR_MODEL_PATH = '<绝对路径>/doclayout_yolo_docstructbench_imgsz1024.pt'
uvicorn app.main:app --host 127.0.0.1 --port 9514 --workers 1
```

就绪必须验证权重加载/哈希、预热和真实图片检测，不能只看到Uvicorn启动消息就算完成。

### 五 xzagent

使用Java17、Maven3.9+，显式设置profile。先按05章初始化模型配置、Agent和Skill资源，确保数据库与Redis配置完整；禁用未使用的飞书/A2A/附件能力。

```powershell
$env:SPRING_PROFILES_ACTIVE = 'local'
$env:NACOS_CONFIG_ENABLED = 'false'
$env:NACOS_REGISTER_ENABLED = 'false'
$env:SERVER_PORT = '9515'
mvn clean package
mvn spring-boot:run
```

在CX配置 `CX_XZAGENT_BASE_URL=http://127.0.0.1:9515`（直连无需/api），设置真实xzagent应用ID/secret和agent-id。提供随机且持久保管的JWT、模型凭证加密及飞书加密密钥，不能沿用模板示例密钥。

### 六 前端

Node满足 `>=20.19.0 <21 || >=22.12.0`；优先使用仓库pnpm锁文件。配置本地 `.env.local`：

```dotenv
VITE_AI_EXAM_PROXY_TARGET=http://127.0.0.1:9511/api
VITE_XZAGENT_BASE_URL=http://127.0.0.1:9515
```

`vite.config.ts` 将浏览器 `/api/cx` 改写为 `/cx`，与目标地址的 `/api` 组合。因此网关模式目标应保留上述 `/api`；直连后端另设目标 `http://127.0.0.1:9513`，但业务请求仍需满足后端身份边界，不应把伪造Header作为正式登录方案。

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

通过CX真实Token登录，再验证enter-chat和xzagent跨域。生产构建执行 `pnpm build`；环境变量通常在构建时进入前端包，不能只改容器运行环境就假定JS中的地址更新。

## 生产部署要点

1. 三个Java服务使用独立镜像与配置；CPU推理单Uvicorn worker，扩容优先多Pod配合服务发现，容量参数要按实际硬件压测。
2. 原Dockerfile依赖公司私有基础镜像。迁到其他环境需获得镜像权限或构建等效JDK/TeX/字体/Python镜像，不能仅复制Dockerfile就保证构建。
3. CX Dockerfile默认 `ARG JAR_FILE=app.jar`，镜像构建前需把打包产物以对应名称放入构建上下文或显式传JAR_FILE。
4. xzagent每个节点配置稳定node-id及集群可达的internal-base-url，跨节点取消与租约管理依赖它。
5. 入口代理须允许长连接SSE并关闭响应缓冲，合理设置空闲超时；WebSocket按实际接口开放Upgrade。
6. cx-py和后端private路径仅内网可达；xzagent调用私网远程工具还需显式配置目标主机/CIDR和端口白名单。
7. 密钥通过Secret/Nacos安全注入。飞书、模型凭据加密密钥变更要考虑既有密文可读性，不是每次启动随机生成后丢弃。
8. 附件、图像、临时文件与Redis事件有各自保留策略；需配合存储生命周期，不以Redis持久化替代业务数据库备份。

## 观测与故障定位

| 现象 | 优先检查 |
|---|---|
| 401 | CX at_/ak_ 与xzagent JWT是否混用、Redis是否共享、过期与应用状态 |
| 503 | Redis/Nacos实例、数据库/模型ready、cx-py容量与服务超时 |
| 登录成功但不能聊天 | xzagent应用凭据、user-login-bind、agent-id、模型快照和Skill资源 |
| 能聊天但不能调用业务 | 远程工具用户凭据/OAuth、Meta URL、私网出站白名单、CX网关 |
| SSE停了但任务继续 | 查询taskId/Run状态，区分连接失败和执行失败 |
| 生成模型启动校验失败 | tasks引用的端点是否存在、type和base-url是否匹配 |
| 飞书显示已绑定但无消息 | 后端真实连接状态、应用权限、enabled、Run租约/执行状态、消息类型 |
| 本地检测不可用 | Python版本、权重哈希、CPU依赖、单worker、预热和容量 |
| 知识点为空 | 树状态、向量维度、Embedding凭据、可见性与候选过滤 |
| 导出字体/图片异常 | 基础镜像、字体、TeX、资源URL策略、图片/内存预算 |

日志保留taskId、runId、appId、实际模型与异常堆栈用于关联。不要在复制日志时暴露Token、完整授权头或含个人数据的Prompt。模型用量表用于业务归因，Trace平台用于链路排查，两者用途不同。
